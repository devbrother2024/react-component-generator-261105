# TDD Rule

> **경고: 이 규칙은 Rigid다. 상황에 맞게 변형하지 마라.** 단계를 건너뛰거나, 순서를 바꾸거나, 예외를 스스로 만들지 마라.

## 우선순위

**프로젝트의 `CLAUDE.md` / `AGENTS.md` 에 TDD 규칙이 있으면 그것이 우선한다.** 이 파일은 프로젝트별 규칙이 없을 때 적용하는 **기본값(fallback)** 이다. 충돌하는 항목만 프로젝트 규칙을 따르고, 나머지는 이 파일을 유지한다.

## 적용 기준

### TDD 필수

- **비즈니스 로직** (계산, 검증, 상태 전이, 데이터 변환)
- **API** (엔드포인트, 요청·응답 처리, 에러 매핑)
- **유틸 / 순수 함수**
- **버그 수정** (버그를 재현하는 실패 테스트를 먼저 작성한다)
- 동작이 있는 훅, 폴백·재시도 같은 제어 흐름

### TDD 불필요

- **타입 정의** (`type`, `interface`)
- **설정 파일** (tsconfig, eslint, vite 설정 등)
- **순수 UI** (동작 없는 마크업·스타일·레이아웃)
- **SQL** (스키마, 마이그레이션)
- 문서, 주석, 정적 자산

판단이 애매하면 **TDD를 적용한다.**

## RED-GREEN-REFACTOR 사이클

### RED: 실패하는 테스트 작성

- **하나의 동작 = 하나의 테스트.** 한 테스트에서 여러 동작을 검증하지 마라.
- 테스트 이름은 기대 동작을 서술한다.
- **반드시 실행해서 실패를 확인한다.** 실행하지 않은 테스트는 테스트가 아니다.
- **실패 이유가 "기능 미구현"이어야 한다.** 문법 오류, import 오류, 오타, 잘못된 셋업으로 인한 실패는 RED가 아니다. 테스트를 고쳐 올바른 이유로 실패시켜라.
- 처음부터 통과하는 테스트는 아무것도 증명하지 못한다. 테스트나 대상이 잘못된 것이다.

### GREEN: 최소한의 코드로 통과

- 테스트를 통과시키는 **최소한의 코드만** 작성한다.
- **YAGNI.** 아직 테스트가 요구하지 않는 분기, 옵션, 추상화를 넣지 마라.
- 실행해서 확인한다. **신규 테스트와 기존 테스트가 모두 통과**해야 한다.
- 테스트를 수정해서 통과시키지 마라. 코드를 고쳐라.

### REFACTOR: 정리

- **중복 제거, 이름 개선, 헬퍼 추출**만 한다.
- **모든 테스트가 green인 상태를 유지한다.** 변경할 때마다 실행한다.
- **새 동작을 추가하지 마라.** 새 동작이 필요하면 다음 RED에서 시작한다.

### 반복

다음 동작에 대한 **RED로 돌아간다.** 요구 사항이 끝날 때까지 한 사이클씩 진행한다.

## 삭제 강제 규칙

**테스트보다 프로덕션 코드를 먼저 작성했다면, 그 코드를 삭제하고 RED부터 다시 시작한다.**

- **"참고용"으로 남기는 것도 금지.** 주석 처리, 별도 파일 보관, 기억해서 다시 쓰기 모두 포함한다.
- 삭제 후 테스트부터 작성하고, 테스트가 요구하는 만큼만 새로 구현한다.
- 기존 코드를 수정하는 경우도 동일하다. 수정부터 하고 테스트를 나중에 붙였다면 수정을 되돌리고 시작한다.

## 변명 차단표

| 변명 | 반론 |
|------|------|
| "너무 단순해서 테스트가 필요 없다" | 단순한 코드가 가장 자주 깨진다. 테스트도 단순하므로 비용이 거의 없다. **단순하면 쓰는 데 30초면 된다.** |
| "나중에 테스트를 추가하겠다" | 나중은 오지 않는다. 사후 테스트는 **구현에 맞춰 쓰이므로 버그를 못 잡고,** 처음부터 통과해 아무것도 증명하지 못한다. |
| "시간이 없다" | 디버깅과 회귀 수정이 훨씬 오래 걸린다. **TDD는 느린 길이 아니라 재작업을 없애는 길이다.** |
| "삭제하면 낭비다" | 이미 쓴 시간은 **매몰 비용**이다. 검증되지 않은 코드를 유지하는 비용이 더 크다. 다시 쓰는 것은 빠르다. |
| "프로토타입이다" | 프로토타입은 프로덕션이 된다. **버릴 코드라면 테스트도 버리면 된다.** 남길 코드라면 TDD로 쓴다. |

## 완료 체크

- [ ] 모든 동작이 실패하는 테스트로 시작했다
- [ ] RED를 실제로 실행했고 실패 이유가 "기능 미구현"이었다
- [ ] GREEN에서 최소 코드만 작성했다
- [ ] 신규 + 기존 테스트가 모두 통과한다
- [ ] REFACTOR에서 새 동작을 추가하지 않았다
- [ ] 테스트 전에 작성한 프로덕션 코드가 남아 있지 않다
